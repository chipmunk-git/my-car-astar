# A* · Pure Pursuit 주행 프로그램 사양

대상: `astar_pure_pursuit_turtlebot.py`

ROS2 Humble에서 정적 점유 지도로 경로를 계획하고, TF에서 읽은 로봇 위치를 이용하여 그 경로를 추종하는 프로그램입니다.

## 1. 구성과 입출력

프로그램은 `AStarPurePursuit` 클래스의 ROS2 노드 하나로 실행됩니다. 노드 이름은 `astar_pure_pursuit`입니다. 지도 수신, 목표 수신, 경로 계획, 속도 제어를 같은 노드에서 처리합니다.

| 구분 | 인터페이스 | 타입 | 역할 |
|---|---|---|---|
| 입력 | `/map` | `nav_msgs/msg/OccupancyGrid` | 점유 지도와 해상도·원점 수신 |
| 입력 | `/goal_pose` | `geometry_msgs/msg/PoseStamped` | 목표 x·y 좌표 수신 |
| 위치 조회 | 지도 프레임 → `base_frame` | TF 변환 | 현재 x·y 좌표와 yaw 조회 |
| 출력 | `/astar_path` | `nav_msgs/msg/Path` | 계획 경로를 RViz에 표시 |
| 출력 | `/cmd_vel` | `geometry_msgs/msg/Twist` | 전진·회전·정지 명령 발행 |

지도 프레임은 수신한 지도의 `header.frame_id`를 사용하며, 비어 있으면 `map`으로 처리합니다. 로봇 프레임의 기본값은 `base_footprint`입니다. `/map` 구독과 `/astar_path` 발행은 깊이 1의 `RELIABLE`·`TRANSIENT_LOCAL` QoS를 사용합니다. 목표 구독과 속도 발행의 큐 깊이는 10입니다.

현재 위치를 `/amcl_pose`에서 직접 구독하지 않습니다. 기존 실습 구성에서는 AMCL이 제공하는 `map → odom`과 로봇 오도메트리의 `odom → base_footprint` 관계를 통해 지도 기준 위치를 조회합니다. 이 노드가 자체적으로 위치를 추정하는 것은 아닙니다.

## 2. 지도 처리와 경로 계획

### 지도와 좌표 변환

- 지도의 너비·높이·해상도와 데이터 길이를 확인하고, 1차원 데이터를 NumPy의 `(height, width)` 배열로 변환합니다.
- 값이 음수인 미확인 셀과 `occupied_threshold` 이상인 셀을 통행 불가로 처리합니다.
- 지도 원점의 x·y와 yaw를 반영하여 월드 좌표와 격자 좌표를 변환합니다. 격자는 `(row, col)` 순서로 다루며, 월드 좌표를 셀로 변환할 때 `floor()`를 사용합니다.
- 경로 셀을 월드 좌표로 변환할 때에는 각 셀의 중심을 사용합니다. 마지막 경로점은 수신한 목표의 정확한 x·y로 교체합니다.

장애물 팽창의 유효 반경은 다음과 같습니다.

```text
유효 반경(m) = max(robot_radius, safety_margin_cells × 지도 해상도)
팽창 반경(칸) = 유효 반경 / 지도 해상도
```

두 여유 거리를 합산하지 않습니다. 해상도 `0.05m`와 현재 기본값을 사용하면 유효 반경은 `max(0.25, 4 × 0.05) = 0.25m`이며, 격자로는 5칸입니다. `circle`은 원형 범위, `square`는 정사각형 범위를 팽창합니다. 이는 지도상의 로봇 중심 통과 영역을 제한하는 설정이며, 실시간 장애물 감지 거리가 아닙니다.

지도 내용과 메타데이터가 이전과 같으면 재처리하지 않습니다. 달라진 지도를 받았고 목표가 남아 있으면 기존 추종 경로를 비우고 재계획을 요청합니다. 잘못된 크기·해상도·데이터 길이의 메시지는 경고 후 무시하며, 이전의 유효한 지도를 반드시 폐기하는 구조는 아닙니다.

### A* 탐색

`astar()`는 시작·목표 셀의 범위와 통행 가능 여부를 확인한 뒤 8방향으로 탐색합니다. 직선 이동 비용은 `1`, 대각선 비용은 `√2`입니다. 목표까지의 행·열 차이를 각각 `dy`, `dx`라고 하면 Octile 휴리스틱을 사용합니다.

```text
h = dx + dy + (√2 − 2) × min(dx, dy)
f = 출발점부터의 최소 누적 비용 g + h
```

`heapq`로 탐색 후보를 관리하고, `best_cost`로 더 작은 누적 비용을 갱신합니다. `parent`를 따라 최종 경로를 복원합니다. 대각선 이동 시 양옆의 직교 셀 중 하나라도 막혀 있으면 이동을 허용하지 않아 장애물 모서리를 관통하지 않도록 합니다. 탐색 실패 시 `None`을 반환합니다.

이 비용은 격자 이동 비용입니다. 실제 주행 시간, 회전 부담이나 벽과의 거리별 가중치는 포함하지 않습니다.

## 3. 경로 추종

제어 루프는 기본 0.10초 주기로 TF를 조회합니다. 새 목표를 받거나 유효한 지도가 변경되어 재계획이 필요하면 A* 경로를 생성한 뒤 추종합니다. 이동 중 주기적인 재계획이나 경로 이탈에 따른 재계획은 구현되어 있지 않습니다.

1. 현재 진행 인덱스 이후의 경로점 중 로봇과 가장 가까운 점을 찾아 진행 인덱스를 갱신합니다.
2. 그 지점부터 순서대로 확인하여 로봇과의 직선거리가 `lookahead_distance` 이상인 첫 점을 주시점으로 선택합니다. 해당 점이 없으면 마지막 경로점을 사용합니다.
3. 주시점 방향과 현재 yaw의 차이를 −π~π 범위로 정규화하여 방향 오차 `alpha`를 구합니다.
4. 방향 오차가 회전 진입 기준 이상이면 전진 없이 제자리 회전하고, 회전 종료 기준 이하가 되면 전진 추종으로 복귀합니다.
5. 최종 목표까지의 거리가 `goal_tolerance` 이하이면 정지하고 목표를 해제합니다. 목표 자세의 방향은 도착 조건에 사용하지 않습니다.

전진 추종의 각속도는 실제 주시점 거리 `d`를 사용하여 계산합니다.

```text
곡률 = 2 × sin(alpha) / max(d, 0.05)
각속도 = 선속도 × 곡률
```

제자리 회전의 각속도는 `1.5 × alpha`를 사용합니다. 두 경우 모두 각속도를 `max_angular_speed`로 제한합니다. 전진 시 선속도는 설정값으로 유지하며, 곡률에 따른 감속은 없습니다. 주시점까지의 연결선이나 실제 회전 궤적의 충돌 여부를 별도로 검사하지 않습니다.

## 4. 파라미터

아래는 소스에서 직접 선언한 14개 파라미터입니다.

| 이름 | 기본값 | 단위 | 역할 |
|---|---|---|---|
| `enabled` | `True` | — | 필요한 입력과 경로가 준비되었을 때 주행 허용 |
| `linear_speed` | `0.05` | m/s | 전진 추종의 선속도 |
| `max_angular_speed` | `0.30` | rad/s | 추종·제자리 회전의 각속도 상한 |
| `lookahead_distance` | `0.25` | m | 주시 경로점 선택의 거리 기준 |
| `rotate_enter_angle` | `1.20` | rad | 제자리 회전 진입 기준, 약 68.8° |
| `rotate_exit_angle` | `0.70` | rad | 제자리 회전 종료 기준, 약 40.1° |
| `goal_tolerance` | `0.15` | m | 최종 목표의 도착 허용 거리 |
| `robot_radius` | `0.25` | m | 장애물 팽창의 최소 반경 설정 |
| `safety_margin_cells` | `4` | 칸 | 격자 단위 장애물 여유 거리 |
| `safety_margin_shape` | `circle` | — | 원형 또는 정사각형 팽창 선택 |
| `control_period` | `0.10` | s | 제어 타이머 주기, 기본 10Hz |
| `occupied_threshold` | `50` | 점유값 | 이 값 이상인 셀을 통행 불가로 처리 |
| `base_frame` | `base_footprint` | — | TF에서 조회할 로봇 프레임 |
| `max_tf_age` | `2.0` | s | 허용하는 TF의 최대 경과 시간 |

속도·주시 거리·회전 기준·도착 기준·주행 허용과 TF 관련 값은 제어 과정에서 읽습니다. `control_period`는 노드 생성 시 적용합니다. `robot_radius`, `safety_margin_cells`, `safety_margin_shape`, `occupied_threshold`는 지도 처리 시 적용하므로, 저장된 지도에서 해당 설정을 바꾸어 시험할 때에는 재실행하는 편이 명확합니다.

코드는 제어 주기와 주시 거리를 각각 최소 `0.05`로 제한합니다. 선속도는 최소 `0`, 각속도 상한은 최소 `0.01`로 처리하며, 회전 종료 기준은 진입 기준을 넘지 않도록 제한합니다. 별도의 전체 파라미터 검증 콜백은 없습니다. ROS2 기본 파라미터인 `use_sim_time`은 위 14개와 별도로 실행 환경에 맞춰 사용합니다.

## 6. 정지 조건과 현재 한계

TF 조회에 실패하거나, TF 시각이 현재보다 `max_tf_age`를 초과하여 오래되었거나 2초를 초과하여 미래이면 위치를 무효화하고 주행을 제한합니다. 시작 후 8초 동안 조회 실패 경고를 억제하지만, 이 시간에 유효하지 않은 위치로 주행을 허용하는 것은 아닙니다.

주행이 허용된 상태에서 경로가 없으면 정지 명령을 발행합니다. 새 목표 수신 시에도 기존 주행을 먼저 정지합니다. 도착 시 정지하고, 일반적인 Ctrl+C 종료에서는 `finally`에서 정지 명령을 발행한 뒤 노드를 정리합니다.

현재 구현의 한계는 다음과 같습니다.

- `/scan`을 직접 구독하지 않아 새 장애물에 대한 실시간 충돌 회피가 없습니다.
- YOLO 검출과 검출에 따른 비상정지는 아직 없습니다.
- 경로점의 통행 가능 여부와 실제 Pure Pursuit 궤적의 충돌 여부는 다르며, 차체·바퀴의 회전 공간을 주행 중 검사하지 않습니다.
- 지도 수신 중단을 시간 기준으로 검사하지 않습니다. TF 시각 검사도 위치 추정의 정확성 자체를 보장하지 않습니다.

## 7. 실행 전제

Ubuntu 22.04 / ROS2 Humble 환경에서 `numpy`, `rclpy`, `geometry_msgs`, `nav_msgs`, `tf2_ros`가 필요합니다. 실제 로봇 주행에는 bringup, 지도 제공, 위치 추정과 초기 위치 설정을 통해 유효한 지도·TF가 준비되어야 합니다. `/cmd_vel`을 발행하는 다른 주행 제어 노드와 동시에 실행하지 않습니다.

필요한 의존성과 ROS2 실행 환경이 준비되면 Python 파일을 직접 실행할 수 있습니다.
