# A* · Pure Pursuit 주행 및 YOLOv8 검출 프로그램 사양

대상: `astar_pure_pursuit_turtlebot.py`

ROS2 Humble에서 정적 점유 지도로 경로를 계획하고, TF에서 읽은 로봇 위치를 이용하여 그 경로를 추종하는 프로그램입니다.

동일한 Python 파일에서 카메라 객체 검출 화면을 제공하는 `detect` 모드도 선택할 수 있습니다. `detect`는 지정된 객체 검출 여부를 ROS2 토픽으로 발행하며, `drive`는 해당 정지 요청을 받아 `/cmd_vel`에 정지 명령을 발행합니다. 기본 실행 모드는 기존과 같은 `drive`입니다.

## 1. 구성과 입출력

주행 모드는 `AStarPurePursuit` 클래스의 ROS2 노드 하나로 실행됩니다. 노드 이름은 `astar_pure_pursuit`입니다. 지도 수신, 목표 수신, 경로 계획, 속도 제어를 같은 노드에서 처리합니다. 다음 표는 주행 모드의 인터페이스입니다.

| 구분 | 인터페이스 | 타입 | 역할 |
|---|---|---|---|
| 입력 | `/map` | `nav_msgs/msg/OccupancyGrid` | 점유 지도와 해상도·원점 수신 |
| 입력 | `/goal_pose` | `geometry_msgs/msg/PoseStamped` | 목표 x·y 좌표 수신 |
| 위치 조회 | 지도 프레임 → `base_frame` | TF 변환 | 현재 x·y 좌표와 yaw 조회 |
| 출력 | `/astar_path` | `nav_msgs/msg/Path` | 계획 경로를 RViz에 표시 |
| 입력 | `/yolo/stop_requested` | `std_msgs/msg/Bool` | 검출 모드에서 정지 요청 수신 |
| 출력 | `/cmd_vel` | `geometry_msgs/msg/Twist` | 전진·회전·정지 명령 발행 |

지도 프레임은 수신한 지도의 `header.frame_id`를 사용하며, 비어 있으면 `map`으로 처리합니다. 로봇 프레임의 기본값은 `base_footprint`입니다. `/map` 구독과 `/astar_path` 발행은 깊이 1의 `RELIABLE`·`TRANSIENT_LOCAL` QoS를 사용합니다. 목표 구독과 속도 발행의 큐 깊이는 10입니다.

현재 위치를 `/amcl_pose`에서 직접 구독하지 않습니다. 기존 실습 구성에서는 AMCL이 제공하는 `map → odom`과 로봇 오도메트리의 `odom → base_footprint` 관계를 통해 지도 기준 위치를 조회합니다. 이 노드가 자체적으로 위치를 추정하는 것은 아닙니다.

## 2. 지도 처리와 경로 계획

### 지도와 좌표 변환

- 지도의 너비·높이·해상도와 데이터 길이를 확인하고, 1차원 데이터를 NumPy의 `(height, width)` 배열로 변환합니다.
- 값이 음수인 미확인 셀과 `occupied_threshold` 이상인 셀을 통행 불가로 처리합니다.
- 지도 원점의 x·y와 yaw를 반영하여 월드 좌표와 격자 좌표를 변환합니다. 격자는 `(row, col)` 순서로 다루며, 월드 좌표를 셀로 변환할 때 `floor()`를 사용합니다.
- 경로 셀을 월드 좌표로 변환할 때에는 각 셀의 중심을 사용합니다. 마지막 경로점은 수신한 목표의 정확한 x·y로 교체합니다.

장애물 팽창의 유효 반경은 다음과 같습니다.

```text
유효 반경(m) = max(robot_radius, safety_margin_cells × 지도 해상도)
팽창 반경(칸) = 유효 반경 / 지도 해상도
```

두 여유 거리를 합산하지 않습니다. 해상도 `0.05m`와 현재 기본값을 사용하면 유효 반경은 `max(0.25, 4 × 0.05) = 0.25m`이며, 격자로는 5칸입니다. `circle`은 원형 범위, `square`는 정사각형 범위를 팽창합니다. 이는 지도상의 로봇 중심 통과 영역을 제한하는 설정이며, 실시간 장애물 감지 거리가 아닙니다.

지도 내용과 메타데이터가 이전과 같으면 재처리하지 않습니다. 달라진 지도를 받았고 목표가 남아 있으면 기존 추종 경로를 비우고 재계획을 요청합니다. 잘못된 크기·해상도·데이터 길이의 메시지는 경고 후 무시하며, 이전의 유효한 지도를 반드시 폐기하는 구조는 아닙니다.

### A* 탐색

`astar()`는 시작·목표 셀의 범위와 통행 가능 여부를 확인한 뒤 8방향으로 탐색합니다. 직선 이동 비용은 `1`, 대각선 비용은 `√2`입니다. 목표까지의 행·열 차이를 각각 `dy`, `dx`라고 하면 Octile 휴리스틱을 사용합니다.

```text
h = dx + dy + (√2 − 2) × min(dx, dy)
f = 출발점부터의 최소 누적 비용 g + h
```

`heapq`로 탐색 후보를 관리하고, `best_cost`로 더 작은 누적 비용을 갱신합니다. `parent`를 따라 최종 경로를 복원합니다. 대각선 이동 시 양옆의 직교 셀 중 하나라도 막혀 있으면 이동을 허용하지 않아 장애물 모서리를 관통하지 않도록 합니다. 탐색 실패 시 `None`을 반환합니다.

이 비용은 격자 이동 비용입니다. 실제 주행 시간, 회전 부담이나 벽과의 거리별 가중치는 포함하지 않습니다.

## 3. 경로 추종

제어 루프는 기본 0.10초 주기로 TF를 조회합니다. 새 목표를 받거나 유효한 지도가 변경되어 재계획이 필요하면 A* 경로를 생성한 뒤 추종합니다. 이동 중 주기적인 재계획이나 경로 이탈에 따른 재계획은 구현되어 있지 않습니다.

1. 현재 진행 인덱스 이후의 경로점 중 로봇과 가장 가까운 점을 찾아 진행 인덱스를 갱신합니다.
2. 그 지점부터 순서대로 확인하여 로봇과의 직선거리가 `lookahead_distance` 이상인 첫 점을 주시점으로 선택합니다. 해당 점이 없으면 마지막 경로점을 사용합니다.
3. 주시점 방향과 현재 yaw의 차이를 −π~π 범위로 정규화하여 방향 오차 `alpha`를 구합니다.
4. 방향 오차가 회전 진입 기준 이상이면 전진 없이 제자리 회전하고, 회전 종료 기준 이하가 되면 전진 추종으로 복귀합니다.
5. 최종 목표까지의 거리가 `goal_tolerance` 이하이면 정지하고 목표를 해제합니다. 목표 자세의 방향은 도착 조건에 사용하지 않습니다.

전진 추종의 각속도는 실제 주시점 거리 `d`를 사용하여 계산합니다.

```text
곡률 = 2 × sin(alpha) / max(d, 0.05)
각속도 = 선속도 × 곡률
```

제자리 회전의 각속도는 `1.5 × alpha`를 사용합니다. 두 경우 모두 각속도를 `max_angular_speed`로 제한합니다. 전진 시 선속도는 설정값으로 유지하며, 곡률에 따른 감속은 없습니다. 주시점까지의 연결선이나 실제 회전 궤적의 충돌 여부를 별도로 검사하지 않습니다.

## 4. 파라미터

아래는 주행 노드에서 직접 선언한 16개 파라미터입니다. 검출 노드의 파라미터는 9절에 별도로 정리합니다.

| 이름 | 기본값 | 단위 | 역할 |
|---|---|---|---|
| `enabled` | `True` | — | 필요한 입력과 경로가 준비되었을 때 주행 허용 |
| `linear_speed` | `0.05` | m/s | 전진 추종의 선속도 |
| `max_angular_speed` | `0.30` | rad/s | 추종·제자리 회전의 각속도 상한 |
| `lookahead_distance` | `0.25` | m | 주시 경로점 선택의 거리 기준 |
| `rotate_enter_angle` | `1.20` | rad | 제자리 회전 진입 기준, 약 68.8° |
| `rotate_exit_angle` | `0.70` | rad | 제자리 회전 종료 기준, 약 40.1° |
| `goal_tolerance` | `0.15` | m | 최종 목표의 도착 허용 거리 |
| `robot_radius` | `0.25` | m | 장애물 팽창의 최소 반경 설정 |
| `safety_margin_cells` | `4` | 칸 | 격자 단위 장애물 여유 거리 |
| `safety_margin_shape` | `circle` | — | 원형 또는 정사각형 팽창 선택 |
| `control_period` | `0.10` | s | 제어 타이머 주기, 기본 10Hz |
| `occupied_threshold` | `50` | 점유값 | 이 값 이상인 셀을 통행 불가로 처리 |
| `base_frame` | `base_footprint` | — | TF에서 조회할 로봇 프레임 |
| `max_tf_age` | `2.0` | s | 허용하는 TF의 최대 경과 시간 |
| `require_detector` | `False` | — | `True`면 검출 상태 수신 전에도 주행 정지 |
| `stop_signal_timeout` | `3.0` | s | 마지막 검출 상태의 최대 유효 시간 |

속도·주시 거리·회전 기준·도착 기준·주행 허용과 TF 관련 값은 제어 과정에서 읽습니다. `control_period`는 노드 생성 시 적용합니다. `robot_radius`, `safety_margin_cells`, `safety_margin_shape`, `occupied_threshold`는 지도 처리 시 적용하므로, 저장된 지도에서 해당 설정을 바꾸어 시험할 때에는 재실행하는 편이 명확합니다.

코드는 제어 주기와 주시 거리를 각각 최소 `0.05`로 제한합니다. 선속도는 최소 `0`, 각속도 상한은 최소 `0.01`로 처리하며, 회전 종료 기준은 진입 기준을 넘지 않도록 제한합니다. 별도의 전체 파라미터 검증 콜백은 없습니다. ROS2 기본 파라미터인 `use_sim_time`은 위 16개와 별도로 실행 환경에 맞춰 사용합니다.

## 6. 정지 조건과 현재 한계

TF 조회에 실패하거나, TF 시각이 현재보다 `max_tf_age`를 초과하여 오래되었거나 2초를 초과하여 미래이면 위치를 무효화하고 주행을 제한합니다. 시작 후 8초 동안 조회 실패 경고를 억제하지만, 이 시간에 유효하지 않은 위치로 주행을 허용하는 것은 아닙니다.

주행이 허용된 상태에서 경로가 없으면 정지 명령을 발행합니다. 새 목표 수신 시에도 기존 주행을 먼저 정지합니다. 도착 시 정지하고, 일반적인 Ctrl+C 종료에서는 `finally`에서 정지 명령을 발행한 뒤 노드를 정리합니다.

주행 제어는 타이머마다 먼저 YOLO 정지 요청을 검사하며, `true`를 받은 콜백에서도 즉시 영(0) 속도의 `Twist()`를 발행합니다. 첫 검출 신호 전에 주행을 금지하려면 `require_detector:=true`로 실행해야 합니다. 신호를 받은 이후에는 기본 3초간 업데이트가 없으면 정지합니다. 검출 대상이 사라진 뒤에는 다음 `false` 메시지를 받아 정상 경로 추종을 재개할 수 있습니다. 이는 특정 객체 인식에 따른 소프트웨어 정지로, 물리적 비상정지 장치가 아닙니다.

현재 구현의 한계는 다음과 같습니다.

- `/scan`을 직접 구독하지 않아 새 장애물에 대한 실시간 충돌 회피가 없습니다.
- YOLO 검출은 별도 모드에서 화면에 표시하며, 지정 객체 검출에 따른 주행 정지 기능을 제공합니다. 다만 모델이 인식하지 못하는 일반적인 벽·판자 등을 검출한다고 보장하지 않으며, 실제 거리를 계산하지 않습니다.
- 경로점의 통행 가능 여부와 실제 Pure Pursuit 궤적의 충돌 여부는 다르며, 차체·바퀴의 회전 공간을 주행 중 검사하지 않습니다.
- 지도 수신 중단을 시간 기준으로 검사하지 않습니다. TF 시각 검사도 위치 추정의 정확성 자체를 보장하지 않습니다.

## 7. 실행 전제

Ubuntu 22.04 / ROS2 Humble 환경에서 `numpy`, `rclpy`, `geometry_msgs`, `nav_msgs`, `std_msgs`, `tf2_ros`가 필요합니다. 실제 로봇 주행에는 bringup, 지도 제공, 위치 추정과 초기 위치 설정을 통해 유효한 지도·TF가 준비되어야 합니다. `/cmd_vel`을 발행하는 다른 주행 제어 노드와 동시에 실행하지 않습니다.

필요한 의존성과 ROS2 실행 환경이 준비되면 Python 파일을 직접 실행할 수 있습니다.

검출 모드에는 추가로 `sensor_msgs`, `cv_bridge`, GUI를 지원하는 OpenCV, Ultralytics와 PyTorch가 필요합니다. 검출 모드에는 지도·TF·목표가 필요하지 않으며, 카메라 영상 토픽과 ROS2 통신, 화면을 표시할 데스크톱 세션이 필요합니다. 실제 실행 순서는 [README](../README.md)에 정리합니다.

## 8. 실행 모드와 프로세스

`dispatch()`가 프로그램 옵션과 `--ros-args ... [--]` 구간을 분리합니다. 프로그램 옵션은 `argparse`로 검사하고, ROS2 인자는 원래 순서로 각 실행 함수의 `rclpy.init(args=...)`에 전달합니다. ROS2 인자 구간의 `--`는 ROS2 옵션의 끝을 의미하며, 이후 프로그램 옵션도 처리할 수 있습니다.

| 명령 | 실행 함수 | 노드 |
|---|---|---|
| `python3 astar_pure_pursuit_turtlebot.py` | 기존 `main()` | `astar_pure_pursuit` |
| `python3 astar_pure_pursuit_turtlebot.py --mode drive` | 기존 `main()` | `astar_pure_pursuit` |
| `python3 astar_pure_pursuit_turtlebot.py --mode detect` | `detect_main()` | `yolo_image_detector` |

실제 로봇 실행 예시에서는 두 모드에 각각 `--ros-args -p use_sim_time:=false`를 명시합니다. 기본 실행 모드는 여전히 `drive`입니다.

두 모드를 각각 다른 터미널에서 실행하면 독립적인 Python 프로세스가 됩니다. 기존 주행 함수·클래스·파라미터와 `main()`의 실행 흐름을 유지하며, 검출용 무거운 라이브러리는 `detect_main()`에서만 불러옵니다.

주행과 검출은 지도·경로 등의 Python 상태를 공유하지 않습니다. 검출 모드는 `/yolo/stop_requested`(`std_msgs/msg/Bool`)을 발행하고, 주행 모드는 이를 구독하여 `/cmd_vel`에 정지 명령을 발행합니다. 검출 모드는 `/cmd_vel`을 직접 발행하지 않습니다. 별도 프로세스로 실행하여도 같은 PC의 CPU·메모리를 사용하므로 주행 제어 주기가 자동으로 보장되는 것은 아닙니다.

## 9. 카메라 객체 검출

### 입력과 처리 흐름

`YoloImageDetector`는 `sensor_msgs/msg/Image`를 구독합니다. 기본 토픽은 실제 영상 표시를 확인한 `/image_raw`입니다. 확인된 발행자는 `v4l2_camera`이며, 구독 QoS는 깊이 1의 `RELIABLE`·`VOLATILE`입니다.

검출 프로세스 내부의 역할은 다음과 같습니다.

1. 수신 스레드에서 `SingleThreadedExecutor.spin_once()`를 실행합니다. `image_callback()`은 메시지와 로컬 수신 시각만 보관하며, 기존 메시지를 최신 메시지로 덮어씁니다.
2. 메인 스레드의 `take_latest_image()`가 보관된 메시지를 가져오고 슬롯을 비웁니다. 두 스레드의 슬롯 접근은 잠금으로 보호합니다.
3. 수신 이후 시간이 `image_timeout` 이내인 메시지를 `CvBridge.imgmsg_to_cv2(..., desired_encoding='bgr8')`로 변환합니다. 최초 메시지의 크기와 실제 `encoding`을 로그에 기록합니다.
4. `model_path`를 해석한 경로를 `YOLO()`에 전달하여 모델을 불러오고 `predict()`를 호출합니다. 기본 모델은 COCO 80개 클래스의 `resources/yolov8n.pt`입니다.
5. `Results.boxes.cls`와 `Results.names`로 검출된 객체 이름을 추출하고 `stop_classes`에 해당하면 `/yolo/stop_requested`에 `true`를 발행합니다. 검출되지 않아도 마지막 검출 시각으로부터 `stop_hold_seconds` 이내라면 정지를 유지합니다. 그 밖에는 `false`를 발행합니다.
6. `Results.plot()`으로 사각형·클래스 이름·신뢰도를 그립니다. 처리 상태 문구를 추가한 뒤 `imshow()`와 `waitKey()`로 화면을 갱신합니다.

추론 중에도 수신 스레드는 최신 메시지를 교체할 수 있습니다. 추론은 ROS2 구독 콜백 안에서 실행하지 않습니다. DDS 구독 큐와 프로그램 내부 대기를 제한하지만, 네트워크·드라이버·추론 단계의 전체 지연까지 제거하거나 모든 프레임을 처리하는 구조는 아닙니다.

### 검출 파라미터

다음 값은 검출 노드 생성 시 읽으며, 변경하여 적용하려면 검출 모드를 다시 실행합니다. 주행 노드의 16개 파라미터와는 별개입니다.

| 이름 | 기본값 | 역할 |
|---|---|---|
| `image_topic` | `/image_raw` | 구독할 카메라 영상 토픽 |
| `model_path` | `resources/yolov8n.pt` | 모델 가중치 경로 |
| `confidence_threshold` | `0.25` | 검출 신뢰도 하한, 0~1 |
| `image_size` | `640` | 추론 입력 크기 설정, 양수 |
| `device` | 빈 문자열 | 비어 있으면 Ultralytics가 장치 선택, 필요 시 `cpu` 또는 GPU 지정 |
| `image_timeout` | `2.0` | 수신 갱신 중단 표시와 오래된 메시지 처리 제한 기준, 초 |
| `stop_classes` | `scissors` | 정지를 유발하는 YOLO 클래스 이름 (쉼표 구분) |
| `stop_hold_seconds` | `1.0` | 마지막 대상 검출 이후 정지를 유지하는 시간 (초) |

`model_path`는 `~`를 사용자 홈 폴더로 확장한 뒤, 상대 경로이면 `astar_pure_pursuit_turtlebot.py`가 있는 폴더를 기준으로 해석합니다. 절대 경로는 그대로 사용합니다. 기본 가중치 `resources/yolov8n.pt`가 없으면 Ultralytics가 다운로드를 시도하며, 이때 인터넷 연결과 파일 쓰기 권한이 필요합니다. 다른 모델도 `model_path`로 선택할 수 있으며, 검출 프로세스 하나에서 지정한 모델 하나를 불러옵니다.

`image_topic`과 `model_path`의 빈 값, 신뢰도 범위, 입력 크기와 수신 제한 시간을 초기화 시 검사합니다. GPU 사용 가능 여부는 이 코드에서 미리 확정하지 않습니다.

### 화면 지표와 종료

- `Inference`: Ultralytics의 `Results.speed['inference']` 값이며 단위는 ms입니다. 영상 수신·변환·결과 그리기·화면 표시를 모두 합친 시간이 아닙니다.
- `Process FPS`: 최근 2초 안에 남은 처리 완료 시각이 둘 이상이면 `(완료 횟수 - 1) / (마지막 완료 시각 - 첫 완료 시각)`으로 계산합니다. 카메라 발행률이나 `1000 / Inference`와 다릅니다. 기록이 하나 이하이면 `0.0`을 표시합니다.
- `Receive age`: 현재 처리 대상으로 가져온 메시지의 로컬 수신 콜백 실행 이후 경과 시간입니다. 카메라 촬영 시각과 ROS2 헤더를 사용한 전체 지연 측정은 아닙니다.
- 최초 영상 전에는 대기 화면을 표시합니다. 마지막 처리 영상의 수신 시각으로부터 기본 2초가 지나면 `IMAGE STREAM TIMEOUT`을 표시하고 상태 전환을 로그에 남깁니다. 카메라 영상 수신 중단과 추론 지연 모두 원인이 될 수 있습니다. 검출 상태를 한 번 수신한 주행 노드는 새 상태 메시지가 3초 넘게 끊기면 정지합니다. 검출 모드 정상 종료 시에는 정지 요청(`true`) 전송을 시도합니다.

ESC·q 또는 Ctrl+C로 종료합니다. 화면 이벤트는 메인 스레드에서 처리하므로 추론이 오래 걸리면 키 입력 반영이 지연될 수 있습니다. 종료 시 수신 스레드를 끝낸 뒤 Executor, 노드, ROS2 컨텍스트와 OpenCV 창을 정리합니다. 수신 처리·영상 변환·모델 로딩·추론 등의 오류는 로그에 남기고 검출 프로세스를 오류 상태로 종료합니다.

기존 단독 검출에서 실제 카메라 영상 변환과 YOLO 검출 동작을 확인하였습니다. 두 모드를 함께 실행하였을 때에도 주행 중 카메라 영상 갱신과 객체 검출을 확인하였습니다. 이후 특정 객체 검출에 따른 주행 정지도 구현하였습니다.
